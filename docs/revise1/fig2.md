カラーバー・スケール・パネル文字・患者情報は画像内に**含まれていない**
(ファイル名にだけ A–D がある)。いずれもスクリーンショットの切り抜きで、RGBA、
縁に 1 px の透明枠が残っている。

**画像は提供されたものをそのまま使う (ken 指示)。** スクリプトは透明画素を白に合成する
だけで、トリミングは一切しない。そのため下表の「縁のゴミ」は出力にもそのまま残る。

## レイアウト

- 幅 170 mm、横 1 列 (1×4、左から A B C D)
- パネルは 40.25 mm の正方形枠 ((170 − 3×3) / 4)、パネル間 3 mm。画像は縦横比を保ったまま
  枠に収め、余りは白 (A がわずかに縦長なので左右に薄い余白が出る)
- ラベルは各パネルの左上**外側** (枠の上 5 mm の余白) に Arial Bold 12 pt (`common.panel_label`)。
  画像の左上角はどれも黒〜暗灰色なので、画像内に載せず外に出した
- 図全体の描画サイズ: 170 × 45.25 mm (高さ = ラベル余白 5 + パネル 40.25)。`common.save()` の
  `bbox_inches='tight'` で四辺に約 2 mm のパディングが付くため、書き出しファイルは
  約 174 × 50 mm (4118 × 1172 px @600 dpi)。他の rev1 図も同じ挙動

## 問題点・懸念

1. **解像度 (1×4 化で 300 dpi 規定は満たす)**
   - パネル幅 40.25 mm (正方形枠なので長辺が 40.25 mm に収まる) での実効解像度:
     A 510 px → **約 322 dpi**、B 496 px → **約 313 dpi**、D 496 px → **約 313 dpi**、
     C 1141 px → **約 720 dpi**。いずれも規定の 300 dpi 以上 (A/B/D はぎりぎり)
   - PNG/TIFF は 600 dpi で書き出しているので A/B/D は約 2 倍の拡大補間。等倍印刷なら
     問題ないが、拡大すると細部はぼやける。余裕を持たせるなら著者に A/B/D の
     高解像度版 (C と同程度、1000 px 角以上) の再書き出しを依頼する。ヒートマップ生成
     スクリプトから直接保存できるならスクリーンショットでなくそちらで
2. 元画像がスクリーンショットのため、縁に別ウィンドウの背景 (A の下端の緑帯) や切れた
   文字 (C の下端) が写り込んでおり、**そのまま出力に残っている** (画像を加工しない方針の
   ため)。目立つのは A 下端の緑帯と C 下端の文字の断片。著者に縁のきれいな版を出し直して
   もらうのが本筋。どうしても本文側で直したいなら、数 px の切り落としで消える
   (初版のスクリプトではそうしていた)
3. C の右上隅の黒い矩形は除去していない (黒背景の上なのでほぼ見えない)。意図的な
   マスクなら問題ないが、著者に確認するのが無難
4. C の右肺野下部に写っている文字列 (モニタ電極?) は患者情報ではないように見えるが、
   念のため著者確認
5. 4 枚の縦横比が少し違う (A が 492×510 で縦長) ため、A だけ枠内で左右に細い白余白が
   出る。気になるなら A を正方形にトリミングすることもできる
6. キャプション (各パネルがどういう症例か、色の意味) は本文側で用意する必要がある。
   カラーバーは元画像に無いので付けていない
